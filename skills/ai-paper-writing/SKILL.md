# 人工智能论文润色SKILL

## 改稿前先明确挑战与贡献

1. **提炼挑战。** 从作者已确认的主张或引言出发，写清论文要完成什么任务，现有做法在什么情形下遇到什么具体困难。读者应能在看到模块名之前理解这个困难。
2. **对应贡献。** 为每项挑战找出本文给出的回答，用一句话说明哪项设计、理论结果或数据资源解决了困难的哪一部分。按实际关系对应，一项贡献可以同时回应多个挑战。
3. **决定本轮改哪里。** 找到读者第一次看见挑战、理解贡献、获得支持证据的位置。根据当前请求，优先补最影响理解的一处。已有定稿引言时沿用其中的表述。只改一句或一个图注时，沿用已有对应关系即可。

起草新稿时，可从一项有证据的发现反推它回答的挑战。理论论文把主张对到定理及其假设，数据集论文把主张对到采集、覆盖或质量验证。遇到证据缺口，写出目前能成立的结论。

根据投稿的研究类型选证据。视觉论文中，声称改善边界定位，就在同一图像区域并列真值与预测，再配支持该判断的边界指标。学习算法论文声称提高样本效率，就在同等样本或标注预算下比较。涉及理论保证时，把结论写在定理允许的假设范围内。会议名称只提供投稿背景，具体版式与材料要求以该届作者指南为准。

作者要审读时，给出位置、读者可能产生的具体误解和建议改句。要求落稿时，使用原稿语言直接修改。局部扩写先连读前后句，补读者缺的一步。压缩时先删表格复述和重复限定，保留比较对象、分母与条件。

## 按当前章节选择写法

| 写作位置 | 具体做法 |
| --- | --- |
| 摘要与引言 | 从可观察的现象引出困难，让读者在遇到模块名之前知道需要解决什么。段落接不上时，找出中间省略的事实，用它从上一段的对象引出下一问。摘要给背景和挑战留出空间，方法写关键动作，结果写能回答主问题的比较及范围。贡献句写清作者做了什么、这个设计解决什么，涉及实测收益时给可核对的依据。试着遮住模块名读一遍，检查句中是否还说清了创新。起草或重构引言、打磨贡献列表时，参阅[五段式 Introduction 写作参考](references/introduction-five-part.md)。 |
| 相关工作 | 围绕一项会影响本文设计的差异组织文献，例如各方法在推理时读到了什么、能输出什么。核对原作的输入、操作和输出，把本研究对基线的适配归在自己的实验设置里。给小节分工、衔接技术路线或选择本文定位的位置时，参阅[方法论文的 Related Work 怎么写](references/related-work.md)。 |
| 方法与公式 | 问题定义先交代推理时可用的输入、目标和输出。先给读者此时能理解的整体关系，内部索引和分支到使用时再定义。对重要的运算顺序，用一个最小例子说明交换顺序会怎样改变输出。逐步核对正文动词、公式和方法图的箭头是否都指向同一个中间量。 |
| 结论 | 对已有证据支持的范围直接下判断。将真正影响推广的一项边界落到具体对象，如分别训练过的医院、区域或模型，以及待检验的迁移场景。让未来工作自然接在该边界后。 |

## 实验小节按目的、设置、结果、结论展开

1. **目的。** 开头点明为什么做这个实验，以及它要回答哪个问题。例如，整体性能已经改善，下一节要查明这种收益能否持续到较长预测时效。
2. **设置。** 交代读懂结果所需的比较对象、条件或指标。与前文完全相同的设置可以略过。如果只有一个条件发生变化，就只说明这一处。消融实验尤其要交代比较双方共同固定了什么。
3. **结果。** 报告直接回答问题的观察。按目的选最有解释力的幅度、趋势、强基线或例外，给出对应的图表与数字。写部件作用时，选能单独检验该部件的对照。
4. **结论。** 回答开头的问题，将观察提炼为对方法设计、适用条件或实际使用有意义的判断。例如，如果逐时效曲线显示收益随时效递减且始终为正，就可以写“收益主要集中在短时效，远端仍有较小收益”。结论的范围随实验覆盖范围确定。

四步描述的是行文顺序，篇幅短时可合成一段。

## 首页图要对应论文的挑战或贡献

回到改稿前梳理的挑战与贡献，先确定读者看完首页图应能复述哪一点。根据论文重点和实际栏宽，决定图的覆盖范围。

- **突出一点。** 选最值得让读者先看到的一个挑战或一项贡献。例如，把两场事件的误差放在同一坐标轴上，读者就能直接看出不同输入何时出现相似的错误。
- **完整呈现挑战或贡献。** 若各项挑战的关系本身就是理解论文的关键，用同一案例或一组可比面板把挑战讲全。若各项贡献如何配合更值得先讲，就展示它们各自带来的变化以及组合后的效果。
- **同时呈现挑战与贡献。** 当读者需要在首页看清问题如何得到回应时，让同一案例贯穿问题与解法，或把每个挑战和对应贡献放在一起。

用引言第一次引用首页图的句子复查成图。把图缩到最终栏宽，读者应能指出哪条曲线、哪组对照或哪个步骤支撑了这句话。图注补足理解所需的单位、基准和选例条件。

## 结果表述与附录取舍

- **结果句写明改善发生在哪一级。** 核对比较对象、指标方向、聚合次序以及计数单位。三个种子的均值改善，与三个种子逐一改善，是两条不同的主张。排名和微小差值从未舍入结果核验。配置、展示子集或案例若在查看测试结果后选定，在解释该结论之处交代选择时点。验证集选检查点、测试后挑配置或子集，是需要分别交代的决定。遇到反例，用一句话写清范围和方向，保留可查的完整结果。
- **按是否改变主结论决定材料位置。** 读者合上附录后，仍应能从正文知道为什么比较、怎么比较、观察到什么、据此能得出什么。将支持关键判断的最小对照放在正文。详细协议、逐种子结果和额外案例可放附录，在有关的论断处指向它们。对一项扎实却偏离主线的实验，先判断删去它会让哪项贡献失去支撑，再决定压缩、移位或删除。

改完沿实际受影响的位置回读。改了贡献句，就查相应的方法、证据与摘要。改了运算或指标名称，就查公式、图注、表头与附录。涉及提交版时按目标会场的当期要求看实际成品，核对受影响页面、图表引用和主文末页。仅做措辞调整时，局部读通且原意、数值与已定稿表述一致即可收口。

需要示范具体改句时，见[改写示例](references/editorial-examples.md)，包含引言过渡、运算顺序、消融对照与结果解读。
